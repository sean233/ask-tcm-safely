它面向整體穩定、希望瞭解日常養生茶、食養、睡眠作息、季節調護、運動恢復、溫和保養或中醫體質傾向的人。它預設一般人不知道該描述什麼，也想不起哪些細節重要，因此會主動用容易回答的問題引導，而不是等待使用者交出一份「完美病史」。

> 這是養生溝通技能，不是疾病診斷、處方門診或急診替代品。一旦對話提示可能存在較嚴重的問題，它會停止養生路線，提供具體的就醫緊迫度和準備建議。

## 為什麼做這個技能

一般 AI 健康對話常見的問題是：

- 讓使用者「詳細說說」，卻沒有告訴他應該觀察什麼；
- 根據一個症狀就武斷地貼上某種體質標籤；
- 只做一次推測，不核對相反表現和其他可能解釋；
- 把所有風險提示一股腦說出來，即使它們並不影響當前決定；
- 用一句「建議看醫生」結束，卻不說明有多急、為什麼去、要準備什麼；
- 在搜尋、複述或摘要中不必要地暴露個人病史。

中醫養生問詢改變的是整個溝通過程。它更像一位穩健、有經驗的養生問詢者：每輪只問少量真正有區分力的問題，說明新答案改變了什麼，保留多個可能方向，並在達到「足以安全試行」而非「百分之百確定」時給出低風險方案。

## 它有什麼不同

| 設計 | 使用者會感受到什麼 |
| --- | --- |
| 主動引導 | 不問空泛的「還有什麼症狀」，而給出可辨識、可選擇的具體感覺 |
| 分輪追問 | 首輪通常 4–5 題，之後只追問 1–3 個最關鍵的問題 |
| 區分時間層 | 把近 2–4 週的當前狀態與過去 6–12 個月的平時狀態分開 |
| 多方向推測 | 在內部保留多個解釋，並核對反證和常見干擾因素 |
| 克制下結論 | 對外最多先說 1–2 個與行動有關的暫定體質傾向 |
| 簡單問題快速通道 | 只問一般食用級飲品時，不強行進行完整體質問詢 |
| 最小可行調理 | 一次只改 1–2 件事，明確觀察點、停止條件和複盤時間 |
| 風險分流 | 需要急救、當日或儘快就醫時，解釋緊迫度和下一步 |
| 靜默篩選 | 與本次決定無關的病史和禁忌用於內部判斷，不反覆製造焦慮 |
| 只在對話中工作 | 不產生報告、病歷、JSON、PDF、表格或其他檔案 |

## 適用範圍

適合這樣的問題：

- 「我整體沒什麼大問題，想找一種溫和的日常飲品。」
- 「我總覺得累，但分不清是睡眠、消化，還是長期體質傾向。」
- 「幫我梳理體質，但不要憑一兩個表現就替我定型。」
- 「我想做一點溫和的飲食、睡眠或作息調整，並知道怎麼複盤。」
- 「我最近的狀態和平時不一樣，幫我把短期變化與長期底子分開。」

不適合用來：

- 確診疾病，或替代身體檢查、檢驗、影像和執業醫師；
- 開治療劑量的中藥方，或把處方包裝成「養生茶」；
- 用自我調理處理急症、快速惡化或明顯功能下降；
- 指導使用者停用處方藥；
- 宣稱 10–20 個問題就能正式判定某種體質。

## 具體互動案例

以下均為合成案例，用來展示問詢方式，不是針對任何人的醫療建議。

### 案例一：使用者不知道怎麼描述「累」

**使用者**

```text
$ask-tcm-safely 我最近總覺得累，想喝點養生茶，但說不清是哪種累。
```

**技能應該怎麼做**

它會先用少量具體問題區分：更像睏得想睡、身體沒力、日常活動後氣短，還是身體沉重、頭腦發矇；什麼時候開始；是否影響日常功能；以及會改變茶飲安全性的少數背景。它不會一開口就斷言「你是氣虛」。

收到回答後，它會簡短說明哪些解釋更像、哪些下降，再只問剩下真正能改變決定的問題，最後進入低風險試行或醫學評估路線。

### 案例二：長期怕冷與近期「熱象」並存

**使用者**

```text
$ask-tcm-safely 我很多年都怕冷，但最近熬夜兩週後口乾、長痘。中醫看我到底是寒還是熱？
```

**技能應該怎麼做**

它會把多年基線與近期熬夜狀態分開，核對口乾是否真的想喝水、熱感在什麼時間出現、睡眠和消化是否同步變化，而不是用一個「寒熱錯雜」把所有現象打包。第一步可以先處理近期干擾，長期傾向則繼續保持為可修正判斷。

### 案例三：只問一種一般食用級飲品

**使用者**

```text
$ask-tcm-safely 我整體沒有不舒服，只想知道一種來源清楚的一般食用級材料能不能偶爾淡泡著喝。
```

**技能應該怎麼做**

走快速通道，只確認 2–3 個直接相關點，例如真正目的、這個材料可能加重的既有不適、相關過敏或特殊人群情況。沒有命中風險時，直接給保守短期試法、觀察點和停止條件，不機械地問滿 18 題。

### 案例四：做體質梳理，但不做 MBTI 式定型

**使用者**

```text
$ask-tcm-safely 你能測一下我是什麼體質嗎？我不知道從哪裡開始。
```

**技能應該怎麼做**

它會先自然接住：「可以，我們做個簡化梳理。」然後從原創的 18 問線索池中分輪選擇問題。線索池參考九種常見基本方向：平和、氣虛、陽虛、陰虛、痰濕、濕熱、血瘀、氣鬱和特稟，但不會計算自創總分，也不會把結果冒充國家標準判定或疾病診斷。

### 案例五：已經不適合繼續養生問答

**使用者**

```text
$ask-tcm-safely 我突然胸口有壓迫感、氣短、冒冷汗，先喝什麼茶緩一下？
```

**技能應該怎麼做**

它不會推薦茶，也不會繼續盤問體質。它會用直白語言說明緊迫程度，列出少量可能的問題類別但不冒充確診，指向急救，並幫助使用者準備聯絡當地緊急服務、隨身藥物資訊等，不提供可能延誤就醫的複雜自我處理步驟。

### 案例六：隱私優先

**使用者**

```text
$ask-tcm-safely 我需要建議，但請儘量少收集個資，也不要重複我不小心寫出來的身分資訊。
```

**技能應該怎麼做**

年齡有關時優先問年齡區間，不問姓名、精確住址、帳號或無關家人資訊；不把個人細節複製到外部搜尋和後續摘要。照片只是可選輔助，如確有幫助，會提醒先裁掉臉、標籤、定位背景等可識別資訊。

## 一般人如何判斷 AI 的養生建議是否可靠

準備嘗試一項茶飲或食養建議前，可以檢查回答是否做到：

- 問清真正目標、時間規律、功能影響和與本次建議有關的安全背景；
- 至少考慮過一個合理的替代解釋或相反表現；
- 說明每種材料為什麼需要，而不是為了顯得專業就堆很多味；
- 區分一般食用級材料、藥性藥材和治療劑量複方；
- 寫清準備方法、保守用量、頻率、短期試用期和不應混用的東西；
- 給出可觀察的改善點、停止條件和明確複盤時間；
- 不承諾「排毒」「根治」，也不讓使用者停用處方藥；
- 出現急症線索時轉向就醫，而不是繼續讓使用者自行試驗。

缺少其中任何關鍵項，都可以在行動前要求再做一次反向審核：

```text
$ask-tcm-safely 在我嘗試上面的建議前，請再審核一遍：核對其他可能解釋和反證、相關用藥與特殊人群風險、每種材料是否必要、保守用法、停止條件，以及就醫是否更安全。只追問真正會改變決定的缺失資訊。
```

也可以用它檢查其他 AI 給出的建議。只貼上建議本身和判斷所必需的最少去識別化背景，不要附帶真實身分資訊。

## 一次完整對話應該如何推進

1. **明確目標**：先找出使用者最想改善的一件事。
2. **風險分流**：只篩查與當前主訴有關、會改變處理的風險。
3. **主動提問**：首輪不超過五個容易回答的問題。
4. **階段綜合**：說明新資訊改變了什麼，哪裡仍不確定。
5. **收窄追問**：再問 1–3 個真正會改變決定的問題。
6. **最小可行方案**：信心足夠後，只給 1–2 個低風險行動。
7. **約定複盤**：說清楚觀察什麼、多久回覆、什麼情況停止或就醫。

在達到真正的行動節點或安全節點前，對話不會半途以「擔心就諮詢專業人士」收場。

## 18 問線索池是什麼

儲存庫內的提問庫是參考問題庫，不是每個人都必須做完的固定測驗。模型應根據當前目標選擇問題，並在每輪回答後調整下一輪。

它會刻意區分：

- 今天是否安全；
- 近 2–4 週的當前狀態；
- 近 6–12 個月相對穩定的平時狀態；
- 支持線索、相反線索，以及熬夜、感染、飲食、藥物、月經、旅行或訓練負荷等一般替代解釋。

它不計算總分。一個暫定體質方向至少需要兩個彼此獨立、能夠重複出現的線索，而且只有會改變當前行動的方向才值得對使用者說出來。

## 隱私設計

本儲存庫不包含任何原始使用者對話、病歷、瀏覽器工作階段匯出、個人身分資訊或模型測試聊天記錄。

技能啟用時，會要求模型：

- 預設按匿名諮詢處理；
- 只收集會改變安全判斷或建議的資訊；
- 不索取真實姓名、證件號碼、精確住址、電話、電子郵件、工作單位和帳號；
- 不在後續回覆中反覆引用使用者主動寫出的無關個資；
- 如需外部搜尋，只使用抽象化後的醫學問題，不帶個人識別細節；
- 照片始終可選，並提醒裁掉臉部、姓名標籤、定位線索等資訊；
- 始終留在對話中，不建立病歷、報告、JSON、PDF 或其他檔案。

這個技能無法控制宿主平台本身的日誌、保留和隱私政策。請同時檢查 Codex、ChatGPT 或其他執行環境的設定。不要在公開 GitHub Issue 中提交可識別的健康資訊。

## 安全設計

技能採用與主訴相稱的風險篩查。對於沒有不適、只問一般茶飲的人，它不會機械朗讀完整急症清單；一旦涉及胸痛、呼吸困難、意識變化、神經功能異常、嚴重出血或脫水、妊娠急症、嚴重過敏或快速惡化，就會明確切換到就醫路線。

兒童、懷孕或哺乳期、明顯高齡衰弱、多藥併用、重要肝腎或心血管疾病、嚴重過敏，以及無法核實草藥與藥物交互作用的人群，不應只憑聊天啟動新的藥性草藥方案。技能仍可協助整理問題、提出風險更低的飲食作息替代方案，並準備與醫師或藥師核對的重點。

## 證據邊界

體質框架參考了現行中國國家標準 [GB/T 46939-2025《中醫體質分類與判定》](https://std.samr.gov.cn/gb/search/gbDetailed?id=473EBB99D729455EE06397BE0A0ABB9A)中的九種基本類型，也參考了公開的 60 題、9 分量表 CCMQ 研究及其與中醫師判斷之間有限到中等的一致性，例如 [Wong 等，2013](https://pmc.ncbi.nlm.nih.gov/articles/PMC3655622/)。

本儲存庫的 18 問線索池是原創內容，不是正式量表的複製，沒有作為量表完成臨床驗證，也不得宣稱為國家標準判定、疾病篩查或診斷。

## 已測試的行為

開發過程中使用不同語言模型進行情境式正向測試，涵蓋：

- 使用者描述模糊時能否主動提問；
- 首輪五題上限；
- 能否按回答自適應追問，而不是機械地跑固定問卷；
- 能否區分近期狀態和長期基線；
- 一般食用級飲品的快速通道；
- 出現急症線索時能否及時切換路線；
- 能否刪去與當前決定無關的醫學旁白；
- 能否保持隱私最小化、只在對話中工作。

這些是行為測試，不是臨床有效性驗證。不同模型和版本的表現可能變化，重要健康決定仍應由合適的醫療專業人員處理。

## 常見問題

### 它會開中藥方嗎？

不會。對於合適、穩定的人群，它可以討論保守的食用級養生選擇。治療劑量藥材、多味複方、身分不明植物或存在明顯交互作用風險的方案，不屬於一般茶飲路線。

### 18 問是不是像 MBTI 一樣替人分類？

不是。它是一個可自適應選擇的線索池，不計算人格測驗式總分，也允許「不確定」、相反證據、短期干擾和多個暫定方向存在。

### 每個人都要回答 18 題嗎？

不需要。大部分具體問題只使用少數相關題。只有使用者明確想做整體梳理時，才可能分幾輪涵蓋更多面向。

### 必須連網或安裝其他工具嗎？

一般使用不需要外部工具。如果確實要核對最新證據或交互作用，模型應使用不含個人身分資訊的抽象問題搜尋。

### 它會儲存健康資料嗎？

技能明確要求模型不建立檔案或紀錄，但宿主平台仍可能依照自己的設定和政策保留對話。

### 能否用於其他智慧代理系統？

儲存庫遵循 Codex 使用的獨立技能結構。其他系統也許能讀取 `SKILL.md`，但其探索機制、指令優先順序、隱私行為和安全表現並未在本專案中驗證。
